# Security implementation

How the SRS security requirements map to code. Policy values live in `config/security.php`.

| SRS | Requirement | Implementation |
|---|---|---|
| 9–14 | Auth, TOTP 2FA, recovery codes | Fortify. Secrets and recovery codes are stored encrypted. Codes are shown once, right after generation (`SecurityController`), and the read-back endpoint is shadowed in `routes/web.php`. TOTP replay is blocked via cache. |
| 11 | Mandatory 2FA by role | `security.two_factor_required_roles` + `EnsureTwoFactorEnrolled`. Owners cannot disable it (`Actions/Fortify/DisableTwoFactorAuthentication`). Admins reset it for lost devices (audited, needs password confirmation). |
| 15 | Password policy | 12–128 chars, no composition rules. Breached-password check (HIBP k-anonymity) in production. Change/reset sends a notification. |
| 16 | Sessions | Database driver, encrypted payload, HttpOnly, SameSite=Lax. Users can list and revoke devices (`SessionManager`). Admins get a 30 min idle and 8 h absolute limit (`EnforceSessionTimeouts`). Password change or reset revokes other sessions and rotates the remember token. |
| 17–18, 79, 112 | RBAC, least privilege, no escalation | Permissions in `App\Enums\Permission`, roles seeded by `RolesAndPermissionsSeeder`. `RoleAssignment`: no self-changes, can only grant roles whose permissions you hold, cannot manage more-privileged users. Role changes require password confirmation and are audited from the package's own events. |
| 20 | Verification | `AlumniVerificationService`: auto-verifies only on exact roll number + programme + year plus a fuzzy name match on an unclaimed record. Everything else goes to manual review. Officers cannot decide their own claim. |
| 22 | Privacy | `ProfileVisibility` filters every read path, including directory filters, so a hidden field cannot be inferred by searching on it. "Connections only" acts as private until Connect ships. |
| 58–61 | OWASP / injection / XSS / CSRF | Eloquent and bound parameters only, LIKE input escaped. Vue escaping (the one `v-html` is the server-generated QR SVG). Profile URLs must be https (no `javascript:`). Laravel CSRF on the web group. |
| 62–64 | Headers + CSP | `SecurityHeaders`: nonce-based script/style CSP with no `unsafe-inline`/`unsafe-eval`, `frame-ancestors 'self'`, nosniff, Referrer-Policy, Permissions-Policy, HSTS when `APP_FORCE_HTTPS`. `CSP_REPORT_ONLY=true` for trials. Ziggy routes are shared as a prop, not an inline script. |
| 66–68 | Rate limits, lockout | Login 5/min per email+IP and 30/min per IP. 2FA 5/min. Registration, reset and password-confirm limited (`ThrottleAuthEndpoints`, since Fortify leaves those unthrottled). Directory search limited. Account locks after 10 failures across password *and* 2FA (`AccountLockout`); admins can unlock. |
| 75–76 | Mass assignment, IDOR | `#[Fillable]` on every model, with verification/status/role fields excluded. Policies on every admin action. Session revocation uses hashed keys, never raw session ids. |
| 77 | Re-authentication | Email/mobile change needs the current password. Role changes, user creation and 2FA reset/disable need password confirmation. |
| 80–82 | Audit + security logs | `AuditLogger` (append-only model, recursive redaction of `security.redact` keys), plus a separate `security` log channel. Pruned after `SECURITY_AUDIT_RETENTION_DAYS` (default 730) by the scheduler. |
| 81 | Correlation | `AssignRequestId`: accepts well-formed upstream `X-Request-ID`, echoes it, adds it to log context and audit rows. Shown on error pages. |
| 83 | Error handling | Outside local/testing, errors render the Inertia `Error` page with the request id, never traces. |
| 87 | DB exposure | MySQL bound to `127.0.0.1` on the host. App uses a non-root user. |
| — | Trusted proxies | Only `TRUSTED_PROXIES`. Never `*`, which would let clients spoof IPs past rate limits. |

## Module-level controls

| Area | Control |
|---|---|
| Connect | Blocks hide both members from each other's directory, profile, feed and mentoring. A blocked member gets the same generic refusal as anyone else, so they can't tell they were blocked. Connection requests are rate-limited (30/hour, 80/day). |
| Privacy | "Connections only" fields are visible to accepted connections, including in directory filters. Mentor matching ignores location the mentor hasn't made visible to the mentee. Contact details are exchanged only when a mentorship is accepted. |
| Feed | Plain text only (no stored HTML). Links rendered client-side, https-only, with `rel="nofollow ugc noopener"`. Member-only group posts never leave the group. Post rate limits. |
| Moderation | Reports are routed by permission: posts and comments → community moderators, jobs → career admins, profiles → user managers. Removal is soft and audited. Group moderators can't act on admins. Batch-group re-enrolment never lifts a ban. |
| Events | Seat allocation under a row lock. Check-in is one atomic update (no double admission). Tickets are 40-char bearer codes, hidden from staff lists. Online links are shown only to confirmed registrants. CSV exports neutralise spreadsheet formulas. Chapter admins can only host for groups they administer. |
| Career | Non-staff posts are moderated, and editing a live post sends it back for review (no bait-and-switch). Application links must be https. |
| Imports | CSV MIME type is sniffed from content, 5 MB / 20k row caps, stored on the private disk, deleted after import. Nothing is written before an explicit confirm by the uploader. Rows are validated individually. |
| Exports | Alumni export needs `alumni.export`, a fresh password confirmation and ≤10k rows, and is audited. Engagement export needs `reports.export` and password confirmation. |
| Staff access | The alumni 360° view shows fields hidden from members, so each view is audited. |
| Notifications | Stored links are relative paths. The open endpoint follows only local paths (no open redirect). |
| Uploads (SRS 71-73) | `FileUploadService` is the only way files enter. Type is sniffed from content, never the client. Images are decoded and re-encoded to WebP, which strips EXIF/GPS and appended payloads. They're resized, thumbnailed and capped at 40 MP (decompression bombs). SVG is refused, and PDFs are checked by magic bytes. ClamAV INSTREAM scanning fails closed with `UPLOADS_SCAN_REQUIRED`. Files get random names on the private disk and are served only by `FileController` after `StoredFilePolicy`, with `nosniff`, a sandboxing CSP, and documents as attachments. Achievement images stay private until published. |
| Messaging (SRS 25) | Participants only, and no admin exception. Strangers can send one request message. Blocks stop both directions. Moderators see only a reported message, never the conversation or a link to it. Attachments are private to participants. |
| Stories & campaigns | Markdown rendered server-side with `html_input: strip` and unsafe links disallowed. This is the only `v-html` besides server-generated QR codes. |
| Communications (SRS 49, 110) | Sending needs `communications.send` and password confirmation, and is audited. Email reaches only users whose *latest* consent is granted. Unsubscribe uses a signed URL: GET only confirms, the signed POST withdraws (RFC 8058 one-click, CSRF-exempt because the signature is the credential). Every consent change is a new row. |
| Donations (SRS 45-47) | Hosted checkout, so no card or UPI data touches the app. The return redirect and webhook are HMAC-verified. Webhook events are de-duplicated (`payment_events`), and the amount is checked against the order. Marking paid is idempotent under a row lock. Receipt numbers are allocated gap-free per financial year under a lock. PAN and address are encrypted at rest and masked in the UI. PAN is required for 80G and for ≥ ₹50,000 (Rule 114B). INR only with a residency declaration (FCRA). Refunds and exports need permission plus password and are audited. The test gateway refuses to run in production. |
| Sign-in with Google / LinkedIn (SRS 10) | Signs in only to an account the identity was linked to while signed in with a password (linking needs password confirmation). A matching email never grants access. Disabled and locked accounts are refused, and 2FA users are handed to the normal TOTP challenge. An identity links to one member only. The OAuth `state` check stops forged callbacks. Links and unlinks are audited. |
| Passkeys (SRS 10) | Fortify's built-in passkeys (`laravel/passkeys`). User verification and discoverable credentials are required, so a passkey sign-in is multi-factor by itself and does not ask for TOTP; privileged users must still enrol in TOTP as a recovery path. Adding or removing a passkey needs password confirmation; only the owner can delete one. Locked or inactive accounts are refused after a valid assertion (`login.blocked_passkey`). Sign-in fires the normal `Login` event, so lockout reset, session limits, new-browser alerts and audit apply. Rate-limited per IP. Registration, verification and deletion are audited. Passkeys are bound to `APP_URL`'s host. |
| Public landing page | `LandingPageService` builds every public item field by field from an allow-list — models are never serialised, so no IDs, emails, phones, roll numbers, online meeting links or notes can leak. Only published/public/approved records are queried (public-audience events, published stories inside their publish date, published honours, published gallery items within their date window). Per-person fields (photo, company, role) honour the alumnus's own privacy settings evaluated for a signed-out viewer, and photos are shown only if their file is public. Geography is aggregate-only, and countries with fewer than 3 alumni are folded into "other" (k-anonymity). Gallery files are public only while the photo is published. Landing settings and gallery changes need `content.manage` and are audited. |
| Media (event/news/profile images) | One pipeline (`storeOptimizedImage`): type sniffed from content (JPG/PNG/WebP only), decoded, pixel-capped, re-encoded to WebP (strips EXIF/GPS and any appended payload), size-limited server-side to the admin-configured limit, random server-side names on the private disk. Visibility of non-public files is derived per request by `PublicMedia` + `StoredFilePolicy`: official event images only while the event is published and public, news images only while published, a profile photo only while the alumnus is featured on the landing page (and the section is shown). Deleted or replaced images are hard-deleted. Gallery management requires the event `update` policy or `content.manage`, and every image is checked to belong to the gallery in the URL. All changes are audited. |
| Admin email changes | `users.manage` within the privilege ceiling, password confirmation, unique-email check, new address must be re-verified, old address notified (masked hint of the new one), audited with old/new values. |
| Admin access | `ADMIN_ALLOWED_IPS` (IPs/CIDRs) restricts `/admin`, and refusals are audited; it relies on `TRUSTED_PROXIES` being correct. Privileged users get an email on sign-in from a browser not seen before, tracked by an encrypted per-account cookie, so IP changes don't cause noise (`LOGIN_ALERTS`: privileged / all / off). |
| Fundraising & paid events | Campaigns go live only after review by `fundraising.manage`. Event fees reuse the donation checkout, webhooks and replay protection (`Payable`). Unpaid seats are held for 30 minutes and then released by `events:release-holds`. Paid registrations can't be cancelled online, so refunds stay with staff. |
| Surveys | Anonymous responses store no user id, only a keyed HMAC of it to stop repeat answers, so staff can't link a response to a person. Eligibility is checked again on submit. |
| AI (SRS 96) | Off by default. Smart search sends no member data. Mentor re-ranking sends anonymous candidates limited to what the mentee can see. Assistant tools are read-only and run as the user, through `ProfileVisibility`, blocks and policies. Prompts treat member-written text as data. Failures fall back to the normal features, and limits are 6/min and 60/day. |

## Tests

`tests/Feature` covers the SRS 104 critical cases: private fields (1), admin access (2), editing others' profiles (3), disabled users (4), session invalidation (5), 2FA disable re-auth (6), single-use recovery codes (7), TOTP replay (8), rate limits (9), URL-id tampering (12), self-assigned admin (13), secrets in logs (14), and production error output (15). Cases 10–11 (uploads) come with the upload module. Each feature module has its own suite under `tests/Feature` (231 tests in total; the browser smoke test also registers a passkey with a virtual authenticator and signs in with it; AI tests use a scripted fake model and never call the API).
